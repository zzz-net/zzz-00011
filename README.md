# 冷链到货温控复核看板

本地纯前端应用，用于冷链到货批次的温度异常识别与人工复核。所有数据存储于浏览器 localStorage，不依赖任何外部服务。

---

## 快速启动

```bash
# 安装依赖（首次）
npm install

# 启动开发服务器
npm run dev
# 浏览器打开 http://localhost:5173

# 类型检查
npm run check

# 代码质量检查
npm run lint

# 生产构建
npm run build
```

页面打开后，点击顶部 **「加载样例数据」** 即可快速体验完整流程。

---

## 三类 CSV 文件说明

所有 CSV 必须使用 **UTF-8 编码**。

### 1. 到货清单（arrival）

导入面板左侧第一张卡片「到货清单」。

| 列名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `batchId` | string | ✅ | 批次号，全局唯一 |
| `productName` | string | ✅ | 产品名称 |
| `arrivalTime` | string | ✅ | 到货时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `requiredTempMin` | number | ✅ | 要求最低温度（°C） |
| `requiredTempMax` | number | ✅ | 要求最高温度（°C） |
| `supplier` | string | ❌ | 供应商 |
| `quantity` | number | ❌ | 数量 |

**示例：**
```csv
batchId,productName,arrivalTime,requiredTempMin,requiredTempMax,supplier,quantity
BATCH-TEST-001,冷藏疫苗 A,2026-06-06 08:30:00,2,8,供应商甲,500
BATCH-TEST-002,冷冻生鲜 B,2026-06-06 09:15:00,-20,-15,供应商乙,200
```

### 2. 运输温度日志（log）

导入面板中间卡片「运输温度日志」。

| 列名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `batchId` | string | ✅ | 批次号，对应到货清单 |
| `timestamp` | string | ✅ | 记录时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `temperature` | number | ✅ | 温度值（°C） |

**示例：**
```csv
batchId,timestamp,temperature
BATCH-TEST-001,2026-06-06 06:00:00,4.5
BATCH-TEST-001,2026-06-06 06:05:00,4.6
BATCH-TEST-001,2026-06-06 06:10:00,11.0
BATCH-TEST-001,2026-06-06 06:15:00,11.2
BATCH-TEST-001,2026-06-06 06:20:00,4.7
```

### 3. 人工复核记录（review）

导入面板右侧卡片「人工复核记录」。

| 列名 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `batchId` | string | ✅ | 批次号 |
| `reviewer` | string | ✅ | 复核人姓名 |
| `conclusion` | string | ✅ | 复核结论，取值：`release`（放行）/ `quarantine`（隔离）/ `ignore`（忽略） |
| `remark` | string | ❌ | 备注 |
| `reviewTime` | string | ❌ | 复核时间，格式 `YYYY-MM-DD HH:mm:ss` |

**示例：**
```csv
batchId,reviewer,conclusion,remark,reviewTime
BATCH-TEST-001,张三,release,超温时间短，产品合格,2026-06-06 16:00:00
BATCH-TEST-002,李四,quarantine,超温严重待评估,2026-06-06 16:20:00
```

---

## 导入顺序建议

```
到货清单 → 运输温度日志 → 人工复核记录
```

三类数据导入不分先后，系统自动按 `batchId` 关联。

## 四类异常手工复现步骤

### 异常一：超温区间

**触发条件**：某批次存在连续 ≥3 条温度日志超出 `[requiredTempMin, requiredTempMax]` 范围。

**复现步骤：**

1. 新建 `arrival_overtemp.csv`：
```csv
batchId,productName,arrivalTime,requiredTempMin,requiredTempMax,supplier,quantity
BATCH-OT-001,冷藏疫苗,2026-06-06 10:00:00,2,8,测试供应商,100
```

2. 新建 `log_overtemp.csv`（中间 3 条超温）：
```csv
batchId,timestamp,temperature
BATCH-OT-001,2026-06-06 08:00:00,4.5
BATCH-OT-001,2026-06-06 08:05:00,4.6
BATCH-OT-001,2026-06-06 08:10:00,10.0
BATCH-OT-001,2026-06-06 08:15:00,11.2
BATCH-OT-001,2026-06-06 08:20:00,10.8
BATCH-OT-001,2026-06-06 08:25:00,4.7
BATCH-OT-001,2026-06-06 08:30:00,4.5
```

3. 在看板依次导入 `arrival_overtemp.csv` → `log_overtemp.csv`
4. **预期结果**：
   - 汇总指标「超温批次」从 0 → 1
   - 异常明细表新增一条，类型标签为红色「超温」
   - 点击左侧展开箭头 → 显示「超温区间明细」表格和温度时间线柱状图，红色柱对应超温点

---

### 异常二：缺日志

**触发条件**：同一批次相邻两条有效温度日志的时间间隔 > 30 分钟。

**复现步骤：**

1. 新建 `arrival_missing.csv`：
```csv
batchId,productName,arrivalTime,requiredTempMin,requiredTempMax,supplier,quantity
BATCH-ML-001,冷藏试剂,2026-06-06 12:00:00,2,8,测试供应商,50
```

2. 新建 `log_missing.csv`（第 1、2 条间隔 60 分钟）：
```csv
batchId,timestamp,temperature
BATCH-ML-001,2026-06-06 10:00:00,4.5
BATCH-ML-001,2026-06-06 11:00:00,4.6
BATCH-ML-001,2026-06-06 11:10:00,4.7
```

3. 在看板依次导入 `arrival_missing.csv` → `log_missing.csv`
4. **预期结果**：
   - 汇总指标「缺日志批次」从 0 → 1
   - 异常明细表新增一条，类型标签为黄色「缺日志」
   - 展开后可见缺失段明细表，显示「上一条 10:00 → 下一条 11:00，间隔 60 分钟」

---

### 异常三：到货未登记

**触发条件**：温度日志或人工复核记录中出现的 `batchId` 在到货清单中不存在。

**复现步骤：**

1. **不要导入任何到货清单**（或导入不含该批次的到货清单）
2. 新建 `log_unregistered.csv`：
```csv
batchId,timestamp,temperature
BATCH-UR-001,2026-06-06 09:00:00,5.0
BATCH-UR-001,2026-06-06 09:05:00,5.1
```

3. 在看板导入 `log_unregistered.csv`
4. **预期结果**：
   - 汇总指标「未登记批次」从 0 → 1
   - 异常明细表新增一条，产品名称显示为「（未登记到货）」
   - 展开后可见关联的温度日志列表

---

### 异常四：复核冲突

**触发条件**：同一批次在人工复核记录中出现不同 `conclusion` 值，或导入的复核记录与页面人工标记结论不一致。

**复现步骤：**

1. 新建 `arrival_conflict.csv`：
```csv
batchId,productName,arrivalTime,requiredTempMin,requiredTempMax,supplier,quantity
BATCH-RC-001,冷藏样品,2026-06-06 14:00:00,2,8,测试供应商,30
```

2. 新建 `review_conflict.csv`（同一批次两条冲突结论）：
```csv
batchId,reviewer,conclusion,remark,reviewTime
BATCH-RC-001,张三,release,初检合格,2026-06-06 15:00:00
BATCH-RC-001,李四,quarantine,怀疑超标,2026-06-06 15:30:00
```

3. 在看板依次导入 `arrival_conflict.csv` → `review_conflict.csv`
4. **预期结果**：
   - 汇总指标「复核冲突」从 0 → 1
   - 异常明细表新增一条，类型标签为玫红色「复核冲突」
   - 展开后可见所有复核记录对比表（张三「放行」 vs 李四「隔离」）

## 失败路径复现

### 场景 1：缺必填列

新建 `bad_missing_column.csv`（故意漏掉 `temperature` 列）：
```csv
batchId,timestamp
BATCH-XXX,2026-06-06 08:00:00
```
导入运输温度日志卡片 → **预期**：红色错误提示「缺少必填列: temperature」，已有数据不受影响。

### 场景 2：坏时间戳

新建 `bad_timestamp.csv`：
```csv
batchId,timestamp,temperature
BATCH-BAD,not-a-date,5.0
BATCH-BAD,2026-06-06 08:00:00,4.8
BATCH-BAD,2026-06-06 08:05:00,4.9
```
导入 → **预期**：
- 导入面板显示黄色警告：「成功 2 条，无效 1 条」
- 展开详情可见「行 2：时间格式错误」
- 第 3、4 行有效数据正常入库，不会被清除

### 场景 3：非数字温度

新建 `bad_temp.csv`：
```csv
batchId,timestamp,temperature
BATCH-BAD2,2026-06-06 08:00:00,abc
BATCH-BAD2,2026-06-06 08:05:00,N/A
BATCH-BAD2,2026-06-06 08:10:00,4.5
```
导入 → **预期**：前 2 行标记为无效（温度非数字），第 3 行正常入库。

### 场景 4：重复导入

任意 CSV 文件导入两次 → **预期**：第二次导入显示灰色提示「该文件已导入，已跳过」，数据不会重复，已有复核标记不受影响。

## 人工复核与导出检查

### 复核操作

1. 在异常明细行，点击「放行」/「隔离」/「忽略」可快速标记
2. 点击铅笔图标打开复核弹窗，可填写备注
3. 复核人姓名可在顶部编辑（默认「质控员」），所有复核决策自动记录复核人与时间戳

### 刷新保留验证

1. 对任意异常点击「放行」
2. 观察「已复核」指标 +1，该行状态变为绿色「放行」
3. **按 F5 刷新页面**
4. **预期**：
   - 顶部复核人姓名保留
   - 所有批次、日志、复核记录完整保留
   - 「已复核」指标和各行状态与刷新前完全一致
   - 备注、复核人、更新时间均不变

### 筛选 → 导出一致性验证

1. 加载样例数据或导入若干 CSV
2. 在筛选栏：
   - 搜索框输入批次号（如 `001`）
   - 勾选「超温」异常类型
   - 勾选「未复核」状态
3. 记录「显示 X / Y 条异常」中的 X 值
4. 点击「导出 CSV」和「导出 JSON」
5. **预期**：
   - 下载的 CSV/JSON 中异常条数 = X（与筛选结果完全一致）
   - CSV 每行包含：批次号、产品名、异常类型、严重级别、描述、原始行号、复核状态、复核人、备注、更新时间
   - JSON 包含：导出时间戳、筛选条件、异常列表、关联批次/日志/复核记录、**当前复核规则快照**

## 规则配置包（导入 / 导出 JSON）

规则配置包可将当前复核规则阈值导出为 JSON，方便跨浏览器、跨人员共享一致的判定标准。

### 导出规则包

1. 在「复核规则配置」面板右上角点击 **「导出规则包」**
2. 系统自动下载 `review-rules-YYYY-MM-DD-HH-MM-SS.json`
3. **预期**：导出的 JSON 包含如下结构：

```json
{
  "packageType": "review-rules",
  "version": 1,
  "exportedAt": "2026-06-06T10:00:00.000Z",
  "exportedBy": "质控员",
  "rules": {
    "overtempThreshold": 0,
    "missingLogIntervalMin": 30,
    "overtempDurationDangerMin": 30,
    "overtempDeltaDanger": 5,
    "missingLogGapDangerMin": 120
  }
}
```

### 导入规则包 + 预览校验流程

1. 在「复核规则配置」面板点击 **「导入规则包」**，选择一个 JSON 文件
2. 系统弹出预览窗口，依次验证：

| 检查项 | 阻断级别 | 显示内容 |
|--------|----------|----------|
| JSON 格式是否合法 | 阻断 | 红色错误信息 |
| `packageType` 是否为 `review-rules` | 阻断 | 红色错误信息 |
| `version` 是否兼容（当前支持 v1） | 阻断 | 版本不兼容提示 |
| 5 个规则字段是否齐全 | 阻断 | 缺字段列表 |
| 每个字段是否为合法数字 | 阻断 | 非数字字段列表 |
| 每个字段是否在合理范围内 | 阻断 | 超范围字段 + [min, max] |

3. **校验通过后**，预览弹窗显示「差异项对比表」：
   - 列：字段名 / 当前值（删除线） / → / 导入值（绿色） / 合理范围
   - 若无差异：提示「所有阈值与当前配置完全一致」

4. **冲突确认**：
   - 若至少一个阈值不同 → 按钮变为橙色 **「确认变更并应用」**，必须点击确认才会覆盖
   - 若完全一致 → 按钮仍为蓝色 **「应用规则包」**

5. **应用成功后**：
   - 异常列表、指标卡、筛选结果立即重新计算
   - 审计日志新增一条 `import_rules_package` 记录，包含：操作人、来源文件名、变更前规则、变更后规则、变更字段列表

### 持久化验证

1. 导入任意规则包，在预览弹窗打开时 **按 F5 刷新页面**
2. **预期**：刷新后预览弹窗依然打开，内容与刷新前完全一致（规则包预览已加入 localStorage 持久化）

### 字段合理范围

| 字段 | 最小值 | 最大值 | 单位 |
|------|--------|--------|------|
| `overtempThreshold` | 0 | 20 | °C |
| `missingLogIntervalMin` | 1 | 600 | 分钟 |
| `overtempDurationDangerMin` | 1 | 600 | 分钟 |
| `overtempDeltaDanger` | 0.5 | 50 | °C |
| `missingLogGapDangerMin` | 5 | 1440 | 分钟 |

## 数据持久化

- 所有数据存储在浏览器 `localStorage`，key：`cold-chain-dashboard-v2`（代码常量见 `src/types/index.ts` 的 `PERSIST_STORAGE_KEY`）
- 包含：到货清单、温度日志、人工复核记录、异常检测结果、复核决策、复核历史、审计日志、复核规则、导入记录、复核人、异常筛选条件、审计筛选条件
- 点击「清空所有数据」按钮可重置（需二次确认）

### 版本迁移边界（v1 → v2）

- **v1**：早期版本使用 key `cold-chain-dashboard-v1`，仅保存基础业务数据（到货/日志/复核/异常/决策/导入记录/复核人/筛选）
- **v2**（当前）：key 升级为 `cold-chain-dashboard-v2`，新增持久化字段：`reviewHistory`、`auditLogs`、`reviewRules`、`auditLogFilter`
- **自动迁移**：系统**未实现** v1 → v2 的自动迁移逻辑。升级后旧 key 下的数据仍保留在浏览器中，但不会被自动读取
- **手动迁移建议**：升级前在 v1 页面执行「导出 JSON」备份，升级到 v2 后如需恢复历史数据，可通过导入 CSV 的方式重新载入

## 异常汇总指标说明

| 指标 | 说明 |
|------|------|
| 总批次数 | 到货清单 + 日志/复核中出现的全部唯一 batchId |
| 超温批次 | 检测到超温区间的批次数 |
| 缺日志批次 | 存在相邻日志间隔 >30 分钟的批次数 |

| 已复核 | 已被人工标记（放行/隔离/忽略）的批次数 |

## 字段映射健康检查与可追溯导入

导入 CSV（到货清单 / 温度日志 / 复核记录）时，系统会弹出「字段映射预览」面板并执行 **映射健康检查**，确保数据来源清晰、异常不静默。

### 健康检查维度

| 检查项 | 严重级别 | 说明 |
|--------|----------|------|
| 沿用本地映射 | ℹ️ 信息 | 已保存的映射全部有效，已自动沿用 |
| 源列失效 | ⚠️ 警告 | 保存的映射指向的 CSV 列在当前文件不存在，**不会静默套用旧映射** |
| 新增列 | ℹ️ 信息 | 当前 CSV 出现保存时未有的列，提示质控员确认 |
| 必填缺失 | ❌ 错误 | 必填字段未映射，阻断导入 |
| 同源冲突 | ❌ 错误 | 同一 CSV 列映射到多个目标字段，阻断导入 |

### 阻断保护机制

- 仅警告（源列失效 / 新增列）：导入按钮变为 **紫色**，需显式勾选「我已确认映射状态」复选框后才能继续
- 阻断错误（必填缺失 / 同源冲突）：「确认导入」按钮完全禁用，必须先修复问题
- 系统 **永远不会** 静默套用已失效的旧映射，所有异常状态必须由质控员显式处理

### 审计日志追溯

所有与映射相关的操作均写入审计日志（可在「审计日志」面板筛选查看），并附带同一份 **映射快照 + 当前表头**：

| 审计操作 | 触发场景 | 元数据 |
|----------|----------|--------|
| `import_blocked` | 预览层检测到健康问题 / 必填缺失阻断 | 文件类型、文件名、原因、失效字段、新增列、当前表头、映射快照 |
| `field_mapping_changed` | 手动修改了任意字段映射 | 文件类型、文件名、变更明细、完整映射快照、当前表头 |
| `import_arrival` / `import_log` / `import_review` | 成功导入 | 文件名、有效/无效行数、映射快照、当前表头 |
| `export_data` | 导出 JSON/CSV | 格式、异常条数、审计日志条数、完整字段映射快照 |

导出 JSON 时自动在根节点附带 `fieldMappings` 字段，结构如下：

```json
{
  "fieldMappings": {
    "arrival": {
      "mappings": [
        { "targetField": "batchId", "sourceColumn": "批次号" },
        { "targetField": "productName", "sourceColumn": "产品名称" }
      ],
      "headers": ["批次号", "产品名称", "到货时间", "..."],
      "savedAt": "2026-06-06T10:00:00.000Z"
    },
    "log": { "...": "..." },
    "review": { "...": "..." },
    "updatedAt": "2026-06-06T10:00:00.000Z"
  }
}
```

### 持久化与隔离

- 映射保存在浏览器 `localStorage`（key: `cold-chain-field-mappings-v1`）
- 三种文件类型 **互不串用**：到货清单 / 温度日志 / 复核记录各自保存独立的映射配置和对应表头
- 刷新页面或重启浏览器后映射仍然保留
- 导入后再导出，JSON 中仍能追溯当时使用的完整映射快照

## 复核交接班功能

质控人员之间将待处理异常整理成清单进行交接，确保异常处理链路完整可追溯。

### 核心工作流

```
创建交接清单 → 接收人查看待办 → 接收/退回 → 逐条复核 → 提交完成
```

### 创建交接清单

1. 点击顶部绿色 **「创建交接」** 按钮
2. **左侧筛选区**：按批次号搜索、异常类型（超温/缺日志/未登记/复核冲突）、严重级别（警告/严重）、复核状态组合筛选异常
3. 勾选需要交接的异常条目（可展开箭头查看原始行号、原复核人、原备注）
4. **右侧交接信息**：
   - 交接标题（可选，默认带时间戳）
   - **接收人（必填）**
   - **截止时间（必填）**
   - 交接备注
5. 每条异常自动保存：原始异常摘要、当前复核规则快照（阈值等）、原复核状态、原复核人、原备注

### 个人待办队列

「复核交接管理」面板提供三种视图：
- **我的待办**（默认）：当前登录人作为接收人的所有待接收/处理中/被退回任务，顶部 Header 红色徽标实时显示数量
- **全部**：所有交接记录
- **我创建的**：当前登录人发起的交接

支持按关键字（标题/ID/人员）、交接人、接收人、状态筛选。

### 接收 / 退回 / 完成

| 操作 | 触发条件 | 效果 |
|------|----------|------|
| **接收** | 状态为「待接收」或「已退回」且当前用户是接收人 | 状态变为「处理中」，记录接收时间 |
| **退回** | 状态为「处理中」且当前用户是接收人 | 填写退回原因，状态变为「已退回」，清除所有条目锁 |
| **完成** | 状态为「处理中」且当前用户是接收人 | 提交复核结论（放行/隔离/忽略），所有结论写入批次复核记录，状态变为「已完成」 |

### 多人同时处理冲突检测

- 点击交接条目进行编辑时，系统自动为该条目加锁（记录锁定人、锁定时间）
- 若另一位质控人员同时尝试编辑同一条目：
  - 界面显示红色冲突提示：**「该条目正在被 XX 处理，请稍后再试」**
  - 审计日志自动写入 `handover_conflict` 记录，包含尝试人、被占用人、时间戳
- 若强制提交，系统弹出**二次确认对话框**明确提示「可能覆盖他人结论」，**不会静默覆盖**

### 刷新保留 / 持久化

全部加入 localStorage 持久化（key: `cold-chain-dashboard-v2`）：
- 交接记录（含状态流转历史、版本号、所有时间戳）
- 条目锁定状态
- 交接筛选条件
- 操作审计日志

刷新页面或重启浏览器后数据完整保留。

### 交接记录导出

在「复核交接管理」面板点击 **「导出 CSV」** 或 **「导出 JSON」**，导出内容与当前筛选结果一致：

**CSV**（双表结构）：
1. 交接记录表：交接ID、标题、状态、交接人、接收人、截止时间、备注、退回原因、完成备注、创建/接收/完成时间、条目数
2. 异常条目表：交接ID、异常ID、批次号、异常类型、严重级别、原复核状态、原复核人、原备注、描述、原始行号、规则快照(JSON)

### 审计日志中的交接相关操作

| 操作类型 | 触发场景 |
|----------|----------|
| `create_handover` | 创建交接清单 |
| `accept_handover` | 接收交接任务 |
| `return_handover` | 退回交接任务 |
| `complete_handover` | 完成交接并提交复核 |
| `handover_conflict` | 尝试编辑已被他人锁定的条目 |

每条操作记录包含：操作人、时间戳、交接ID、条目数、原因/备注等元数据，可在「审计日志」面板中筛选查看。
